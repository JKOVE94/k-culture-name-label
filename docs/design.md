# 일본선교 이름 라벨 부스앱 — 설계 문서 v0.5

- 작성: 2026-11-11 (v0.1) / 갱신: 2026-11-12 (v0.2 ~ v0.5)
- 대상 일정: 출국 1~3개월 전 (아래 일정은 출국일 = D 기준)

## 전제 조건 (확정)
| 항목 | 내용 |
|---|---|
| 인쇄 담당 기기 | **iPhone만** |
| 입력 기기 | **방문자 본인 폰 + 팀원 개인 폰** (데이터 통신은 보통 되지만 안 되는 상황도 대비) |

| 통계 | 앱은 **인쇄 횟수만** 자동 기록. 성별·연령층은 **부스 스태프가 직접 입력** (방문자에게 묻지 않음) |

### v0.10 변경 요약 (통계 모으기)
1. 인쇄 기록 형식: `{ id: 기기ID-일련번호, at, dev, dir, reprint, gender, age }`. 이름 없음. 인쇄 폰마다 「이 폰 이름」을 설정한다.
2. **B(수동, 사용 중)**: 인쇄 폰 → QR(조각당 약 25건, `NLS1:` 형식) / JSON 파일 / 텍스트 복사 → 리더 폰 `stats.html`에서 합치기(id 기준 중복 제거). 집계와 CSV 다운로드. `stats.html`은 Service Worker로 오프라인 동작.
3. **A(자동, 준비됨·꺼짐)**: `supabase.mjs` 설정 + `supabase/migrations/20261113000000_print_events.sql`(RLS: anon insert·select). 다음 스캔 또는 2분 후 기록을 확정하고, 온라인일 때 모아서 업로드(`on_conflict=client_id`, ignore-duplicates).
4. Niimbot 공식 앱에는 외부에서 인쇄를 요청하는 공개 수단이 없다. 비상시에만 PNG 저장 → 공식 앱에서 불러와 인쇄한다.

### v0.9 변경 요약 (스태프 화면 오프라인)
1. **`print.html`을 한 파일로 빌드** (`scripts/build-staff.mjs`, esbuild): jsQR·niimbluelib·라벨 렌더러·QR 해석을 모두 포함 (약 390KB). 열린 뒤에는 네트워크 요청 0회.
2. **HTTP 캐시로 재실행**: `print.html`만 `Cache-Control: public, max-age=86400`. 온라인일 때마다 `fetch(cache:'reload')`로 캐시를 갱신한다. Chromium에서 서버를 끈 뒤 다시 열기와 라벨 생성까지 확인했다. Bluefy(WKWebView)는 실기 확인이 필요하다.
3. **운영 보조**: 온라인/오프라인 띠, 오프라인 중 닫기·새로고침 경고, 화면 꺼짐 방지(Bluefy `setScreenDimEnabled` → Wake Lock), 빌드 버전 표시와 「업데이트 확인」.
4. Service Worker가 되는 브라우저(Android Chrome 등)에서는 SW로 완전 오프라인.

### v0.8 변경 요약 (배포·오프라인)
1. **배포: Vercel 정적 사이트** (Root `app`, 빌드 없음). Cloudflare Pages 대신 Vercel을 쓴다. 서버 함수가 없어 리전 문제가 없다. Supabase는 여러 폰의 기록·표기 사전을 모을 때 붙인다 (미구현).

3. **PWA**: manifest, 아이콘, `sw.js`.

   - HTML: 네트워크 우선(3초 초과·오류 시 저장본)
   - 사전: 홈 화면 웹앱으로 열 때만 통합본 저장. 오프라인에서 조각 요청이 오면 통합본에서 만들어 응답 (4,222개 전부 일치 확인)
   - 화면 아래 「✅ オフラインでも使えます」 표시
4. **vercel.json**: sw.js·HTML은 no-cache, 사전 7일(+30일 stale-while-revalidate), vendor·아이콘 30일.

### v0.7 변경 요약
1. **프린터를 Niimbot B1 Pro로 변경**: 300dpi, 인쇄 헤드 567px → 50×30mm 라벨 = **567×354px**. 라벨 디자인은 그대로 두고 해상도에 맞게 통째로 확대한다. 연결된 프린터의 해상도를 읽어 자동으로 맞추고, B1(203dpi)도 그대로 지원한다.
2. **동시 연결**: B1 Pro는 공식 사양상 iOS 3대 + Android 7대까지 동시에 연결된다. Bluefy(Web Bluetooth)에서도 여러 대가 동시에 붙는지, 두 대가 거의 동시에 인쇄할 때 작업이 섞이지 않는지는 **실기 확인 항목**이다.
3. **방문자 화면에서 흑백 라벨 미리보기 제거**. 완료 창은 QR + 「スタッフがあなたの名前シールを印刷します」 + 컨러 이름카드 저장만 남긴다. 흑백 라벨은 스태프 화면에서만 보인다.
4. (선택) B1 Pro는 전용 라벨을 쓰면 **빨강+검정 2색 인쇄**와 회색조 인쇄도 지원한다. 하트·색동 줄만 빨강으로 찍는 버전은 프린터와 라벨을 받은 뒤 검토한다.

### v0.6 변경 요약
1. **방문자 완료 창**: 「できた！」를 누르면 QR + 「このシールが印刷されます」(흑백 라벨 미리보기) + 「名前カードをスマホに保存」을 보여 준다.

## 1. 목표

| 방향 | 입력 | 출력 |
|---|---|---|
| 한국 이름 → 일본어 | 한글 (예: 김, 민준, 김민준) | 가타카나 (キム, ミンジュン, キム・ミンジュン) |
| 일본 이름 → 한국어 | 한자 (예: 田中) → 읽는 법 선택 (たなか) | 한글 (다나카) |
| 일본 이름 → 한국어 | 히라가나·가타카나 (예: たなか, タナカ) → 읽기 선택 없음 | 한글 (다나카) |

입력이 끝나면 **QR**이 생성되고, 인쇄 담당 iPhone이 스캔하면 블루투스 라벨프린터로 **즉시 인쇄**된다.

### 성공 기준
1. QR 스캔부터 라벨이 나오기까지 **3초 이내**
2. 인쇄 경로에 **서버 호출 0회**. 네트워크가 끊겨도 인쇄된다 (인쇄 횟수 업로드는 나중에)
3. 일본 이름의 읽는 법은 **사전 추천을 먼저 보여 주고**, 없으면 히라가나로 직접 입력한다
4. 스태프가 결과를 고치면 **표기 사전에 저장**되어 다음부터 자동으로 적용된다

## 3. iPhone 인쇄 경로: Bluefy

### 3.1 제약과 대응
| 제약 | 대응 |
|---|---|
| iOS Safari와 홈 화면 웹앱에는 Web Bluetooth가 없다 | 인쇄 담당 iPhone만 **Bluefy**를 쓴다. 입력 폰은 Safari로 충분 |
| Bluefy(WKWebView)에서는 **Service Worker가 동작하지 않는다**. 오프라인 상태에서 처음부터 다시 열 수 없다 | **"한 번 열면 끝까지"** 방식: 시작할 때 앱, 사전, 폰트 확인, 표기 사전을 모두 메모리와 IndexedDB에 올리고 이후 네트워크 요청 0회. 행사 중에는 **탭을 닫지 않는다** (§11) |
| Bluefy에서 Niimbot B1이 장치 목록에 안 보였다는 사례가 있다. 같은 회사 M2-H·D110은 Bluefy에서 인쇄된 사례가 있고, **iPhone에서는 장치 이름이 비어 보일 수 있다**는 기록이 있다 | 장치를 **이름 대신 BLE 서비스 UUID로 찾는다**. 그래도 안 되면 전체 장치 표시로 연결한다. 실기 검증 항목에 넣는다 |

### 3.2 프린터 검증 절차 (D-7주, B1 도착 직후)
1. iPhone + Bluefy로 `niim.blue`에 접속해 B1이 장치 목록에 보이는지, 50×30 인쇄가 되는지 확인한다.
2. 자체 테스트 페이지(서비스 UUID로 찾기 / 전체 장치 표시 두 가지 방식)로 다시 확인한다.
3. 인쇄된 라벨에서 한글, 가타카나, 한자 선명도와 농도(1~5)를 확인한다.
4. 판정
   - **성공** → B1 1대를 추가 구매해 총 2대
   - **실패** → Bluefy에서 동작 확인된 **58mm ESC/POS BLE 감열 프린터 + 감열 라벨 롤**로 교체 (2대)
5. 비상 수단 확인: 라벨 PNG를 사진에 저장한 뒤 **Niimbot 공식 앱에서 이미지로 인쇄**되는지 본다. 공식 앱이 오프라인에서 되는지도 확인한다.

### 3.3 인쇄 담당 iPhone 구성
- 메인 1대 + 예비 1대 (둘 다 Bluefy 설치, 프린터 1대씩 연결 가능)
- 자동 잠금 끄기, 저전력 모드 끄기, 보조배터리 연결
- 행사 시작 전에 **데이터가 되는 곳에서 앱을 열고 "준비 완료" 표시를 확인**한다 (§11)

## 4. 시스템 구성

```
┌───────────────────────────┐   ┌──────────────────────────────┐
│ ① 방문자 본인 폰 (Safari)   │   │ ② 팀원 개인 폰 (홈 화면 웹앱)   │
│  접속 QR 포스터로 진입        │   │  출국 전 설치, 완전 오프라인     │
│  사전: 첫 글자별 조각 로딩     │   │  사전 전체 + 표기 사전 저장      │
└────────────┬──────────────┘   └───────────────┬──────────────┘
             │      결과 QR (변환 데이터 자체)             │
             └──────────────────┬──────────────────────┘
                                ▼
             ┌─────────────────────────────────────┐
             │ ③ 인쇄 담당 iPhone (Bluefy)           │
             │  QR 스캔 → 확인·수정 → 라벨 생성        │
             │  → 인쇄 대기열 → BLE 전송               │
             │  인쇄 횟수(+스태프 입력 성별·연령층)     │
             │  + 표기 수정 → IndexedDB 대기열          │
             └───────┬─────────────────────┬───────┘
                     ▼ BLE                 ▼ 온라인일 때만 (몰아서)
             ┌──────────────┐     ┌──────────────────────────┐
             │ Niimbot B1 ×2 │     │ Supabase 도쿄               │
             └──────────────┘     │  print_events (횟수)        │
                                  │  spelling_overrides (표기)  │
                                  └──────────────────────────┘
                                               ▲ 표기 사전 내려받기 (①②③)
```

## 6. 이름 변환 명세

### 6.0 "불리고 싶은 이름" 한 칸 입력 (프로토타입 `input.mjs` 검증 완료)

처음 만난 사이에서는 보통 성으로 불리기를 원하므로, 성/이름을 강제로 나눠 받지 않고 **불리고 싶은 이름을 한 칸에** 적게 한다.

| 언어 | 제목 | 보조 문구 | 예시 (placeholder) |
|---|---|---|---|
| 日本語 | 呼ばれたい名前を書いてください | 苗字だけでも、下の名前だけでもOK。漢字・ひらがな・カタカナ、どれでも書けます | 例）田中　さくら　タナカ |
| 한국어 | 불리고 싶은 이름을 적어 주세요 | 성만, 이름만, 전체 이름 모두 괜찮아요 | 예) 김 / 민준 / 김민준 |

**글자 종류로 방향과 처리를 자동 판별**한다. 방향 선택 화면은 없다.

| 입력 | 판별 | 처리 |
|---|---|---|
| 한글만 | `ko2ja` | 바로 가타카나 변환 |
| 히라가나·가타카나만 | `ja2ko` | 읽기 단계 없이 바로 한글 변환 |
| 한자 포함 | `ja2ko` | 읽기 후보 선택(§7) → 한글 변환 |
| 그 외 (로마자 등) | — | "ひらがな・カタカナで書いてください" 안내, 또는 스태프가 직접 입력 |

**띄어쓰기와 나누기**
- 공백, 전각 공백, `・`가 있으면 그 기준으로 나눠 각각 변환한다.
- 한국어를 붙여 쓰면 흔한 성씨로 자동 분리한다. 3글자는 첫 글자가 성씨일 때, 4글자는 남궁·제갈 등 두 글자 성씨일 때 나눈다. 2글자는 "민준"(이름만)인지 "김준"(성+이름)인지 알 수 없어 나누지 않는다.
- 일본어 한자를 붙여 쓰면(田中翔) 성 사전과 이름 사전을 둘 다 맞춰 보면서 **경계를 자동으로 찾는다** (田中|翔).
- 한 덩어리만 있으면 성 사전과 이름 사전을 **모두** 찾아 후보를 합친다.
- 한자와 가나가 섞인 이름(美ゆき 등)은 사전에 있으면 후보로, 없으면 직접 입력(가나 부분은 미리 채움)으로 처리한다.

```
김         → キム                  민준      → ミンジュン
김민준     → キム・ミンジュン        남궁민수  → ナムグン・ミンス
タナカ     → 다나카                 たなか    → 다나카
タナカ ショウ → 다나카 쇼            田中翔    → 田中|翔 분리 → 읽기 선택 → 다나카 쇼
```

성/이름 구분을 알면 `part`를 `family`/`given`으로, 모르면 `any`로 둔다. 출력할 때는 구분자로 잇는다 (가타카나는 `・`, 한글은 공백).

**변환 우선순위** (프로토타입 `convertPart` 구현·검증 완료)
```
1) 표기 사전: (방향, 성/이름, 원문) 정확히 일치   예) なつき(이름) → 나츠키
2) 표기 사전: (방향, 공통, 원문) 정확히 일치
3) 규칙 변환 (§6.1, §6.2)
```

### 6.1 한글 → 가타카나 (규칙)
1. 한글 음절을 초성·중성·종성으로 분해한다.
2. 초성 ㄱㄷㅂㅈ의 유성음화
   - 이름 각 부분의 첫 글자, 또는 막힌 받침 뒤 → 무성음 (김→キム, 지훈→チフン)
   - 모음이나 울림 받침(ㄴ·ㅁ·ㅇ·ㄹ) 뒤 → 유성음 (민준→ミンジュン, 수빈→スビン)
3. 모음: ㅓ·ㅗ→オ, ㅡ·ㅜ→ウ, ㅐ·ㅔ→エ, 이중모음은 작은 가나 (권→クォン, 황→ファン, 최→チェ)
4. 받침: ㄱ→ク, ㄴ·ㅇ→ン, ㅁ→ム, ㄹ→ル, ㅂ→プ, ㅅ·ㄷ 계열→ッ
5. 성씨처럼 표기가 갈리는 경우(이→イ/リ, 노→ノ/ロ)는 표기 사전으로 처리한다.

```
김→キム  박→パク  최→チェ  권→クォン  황→ファン  곽→クァク
민준→ミンジュン  지훈→チフン  서연→ソヨン  예준→イェジュン  철수→チョルス
```

### 6.2 히라가나 → 한글 (규칙, 국립국어원 표기법 기반)
1. 가타카나로 입력해도 히라가나로 정규화한다. 장음 부호 `ー`는 생략한다 (ユーキ→유키).
   - 가타카나 외래 표기도 처리한다: シェ→셰, ジェ→제, チェ→체, ウィ→위, ヴィ→비, ティ→티, ファ→파 등 (ジェシカ→제시카, ヴィヴィアン→비비안)
   - 한계: 외국 이름은 규칙만으로 굳어진 한글 표기가 안 나온다 (ウィリアム→위리아무, 굳어진 표기는 윌리엄). 스태프가 고치고 표기 사전에 저장한다.
2. 어두와 어중을 구분한다: か·た행과 ち는 어두에서 예사소리, 어중에서 거센소리 (たなか→다나카, ちひろ→지히로)
3. ん→ㄴ 받침, っ→ㅅ 받침 (かっぺい→갓페이)
4. 장음 생략: おう·おお→오, うう→우 (さとう→사토, ゆうき→유키). 단 えい는 유지한다 (けいこ→게이코).
5. **「つ」 기본 규칙 = `auto`: 어두는 `츠`, 어중은 `쓰`**
   - つき→츠키, つばさ→츠바사, まつや→마쓰야, てつや→데쓰야
   - 규칙과 다르게 굳어진 이름은 표기 사전으로 덮어쓴다 (예: なつき→나츠키, まつもと→마츠모토)
   - 설정에서 `auto` / `쓰` 고정 / `츠` 고정을 고를 수 있다

### 6.3 표기 사전 (spelling overrides)
목적: 이름마다 굳어진 표기를 **한 번 정해 두면 계속 쓴다**. 성과 이름은 어느 정도 정해진 집합이라 쌓일수록 정확해진다.

| 항목 | 내용 |
|---|---|
| 종류 `kind` | `ja2ko` (히라가나 → 한글), `ko2ja` (한글 → 가타카나), `ja_reading` (한자 → 히라가나 읽기) |
| 범위 `part` | `family`(성) / `given`(이름) / `any`(공통) |
| 키 / 값 | `source` → `value` (예: `まつもと` → `마츠모토`, `이` → `リ`, `翔` → `かける`) |
| 초기 데이터 | 출국 전에 팀이 미리 입력한다 (흔한 성씨 + 「つ」가 들어간 흔한 이름부터) |
| 추가 방법 1 | 인쇄 화면에서 스태프가 결과를 고치면 **"이 표기를 사전에 저장할까요? (まつもと → 마츠모토)"** 확인 → 저장 |
| 추가 방법 2 | 관리 화면(P6)에서 직접 추가, 수정, 삭제 |
| 적용 | 저장 즉시 그 기기에 적용. 온라인이 되면 Supabase에 올리고, 다른 기기는 다음 동기화 때 받는다 |
| 충돌 | 같은 키에 값이 여러 개면 **가장 최근 값**을 쓴다. 관리 화면에서 정리 |
| 개인정보 | 성과 이름을 **각각 따로** 저장하고, 사람·시각·인쇄 기록과 연결하지 않는다 (§12) |

> 「つ」뿐 아니라 장음 표기(유키 / 유우키), 한국 성씨(이 / 리) 같은 다른 예외도 같은 방식으로 처리한다.

### 6.4 호칭 선택 (프로토타입 `honorific.mjs` 검증 완료)

이름 입력 칸 바로 아래에 **"어떻게 불리고 싶은지"**를 고르는 칩 4개를 둔다. 기본값은 `さん`이다.

```
呼ばれたい名前を書いてください
[ 田中                    ]

どう呼ばれたいですか？
( さん )  ( くん )  ( ちゃん )  ( 名前だけ )
→ 다나카 상
```

| id | 일본어 칩 | 한국어 칩 | 라벨 (ja2ko, 일본인) | 라벨 (ko2ja, 한국인) |
|---|---|---|---|---|
| `san` | さん | 상 (さん) | 다나카 상 / 田中さん（たなか） | キムさん / 김 |
| `kun` | くん | 군 (くん) | 다나카 군 / 田中くん（たなか） | キムくん / 김 |
| `chan` | ちゃん | 짱 (ちゃん) | 다나카 짱 / 田中ちゃん（たなか） | キムちゃん / 김 |
| `none` | 名前だけ | 이름만 | 다나카 / 田中（たなか） | キム / 김 |

- 한글 호칭은 표기법(산·쿤·찬)이 아니라 **흔히 쓰는 표기(상·군·짱)**로 고정한다. 한국 팀원이 읽고 부르기 위한 것이기 때문이다.
- 한글 쪽은 띄어 쓰고(다나카 상), 일본어 쪽은 붙여 쓴다(キムさん).
- 호칭을 붙이면 글자가 길어지므로 라벨 큰 줄의 글자 크기 자동 맞춤(§9.1)에 호칭까지 포함해 계산한다.
- 스태프도 인쇄 화면(P2)에서 호칭을 바꿀 수 있다.
- 기본값 `さん`은 설정(P5)에서 바꿀 수 있다.

## 7. 한자 → 읽는 법

### 7.0 기본: ふりがな 자동 입력 (테스트 페이지 `proto/index.html`)

일본인은 한자를 쓸 때 반드시 키보드에 읽기를 먼저 친다. 키보드에는 이미 "히라가나 → 한자" 변환 사전이 있고, 그 사람이 자주 쓰는 이름은 학습도 되어 있다. 웹에서 키보드 사전을 직접 부를 수는 없지만, **변환 직전에 친 히라가나는 브라우저 표준 이벤트(composition)로 받을 수 있다.** 서버 없이 JS만으로 된다.

**화면에 보이는 입력칸은 하나뿐이다 (v0.5.2).** 읽기는 입력칸이 아니라 칩과 미리보기의 후리가나(ruby)로 보여 준다.

```
呼ばれたい名前を書いてください
[ 田中                    ]          ← 유일한 입력칸

読み方はどれですか？                   ← 한자가 있을 때만 나타남
(たなか●) (やなか) (でんちゅう) (その他)

どう呼ばれたいですか？
(さん●) (くん) (ちゃん) (名前だけ)

┌ 미리보기 ───────────┐
│      다나카 상       │
│   たなか             │   ← 한자 위에 작은 후리가나
│   田中さん           │
└────────────────────┘
```
- 읽기 칩 1위는 키보드 힌트 + 이름 사전으로 자동 선택된다. 대부분은 손댄 필요가 없다.
- 맞는 읽기가 없으면 `その他`를 누른다. **아래에서 올라오는 시트**에서만 히라가나를 입력하고, 닫으면 다시 입력칸 하나만 남는다. 직접 입력한 읽기는 칩 맨 앞에 추가된다.
- 가나로만 쓰거나 한글로 쓰면 읽기 줄 자체가 나타나지 않는다.

- **ふりがな는 이벤트를 따라가며 쌓지 않고, 매번 입력칸의 현재 값에서 다시 계산한다.** (iPhone 실기 테스트 결과: 이벤트 값만 따라가면 끝 글자가 빠져 さくら→「さく」, たなか→「たな」가 됐다)
  - 가나 부분: 입력칸에 실제로 들어간 글자를 그대로 읽는다 (추측 없음).
  - 한자 부분: 키보드에서 잡은 히라가나는 **힌트**로만 쓴다. 이름 사전 후보 중 힌트와 앞부분이 맞는 것을 1위로 올리고, 사전에 없으면 힌트 자체를 쓴다. 끝 글자가 빠진 힌트(たな)도 田中 → たなか로 복원된다.
  - 한자 밑에 읽기 후보 칩을 항상 보여 주고, 누르면 ふりがな가 바뀜다.
- 성과 이름을 따로 변환하면 힌트를 이어 붙인다 (たなか→田中, しょう→翔 ⇒ 田中翔 = たなか しょう).
- ローマ字 키보드의 조합 중 알파벳(たなn)은 떼고 읽는다.
- 가나로만 쓰면 ふりがな는 입력과 같다 (タナカ → たなか).
- 본인이 ふりがな를 직접 고치면 그 뒤로는 자동 입력을 멈춘다.
- 한글 결과는 **ふりがな 칸을 기준으로** 만든다. 한자는 라벨 표시에만 쓴다.

**왜 숨은 힌트가 아니라 보이는 칸인가**
- 이름의 실제 읽기로는 변환이 안 돼서 다른 읽기로 쳤을 수 있다 (大翔를 だい+しょう로 입력). 칸이 보이면 「だいしょう」을 보고 본인이 「はると」로 고친다.
- 「氏名＋フリガナ」는 일본 웹 양식에서 매우 흔한 형태라 방문자에게 낯설지 않다.

**자동 입력이 안 되는 경우 → §7.1~7.3의 사전 후보로 대체**
- 붙여넣기, 자동 완성, 필기·음성 입력, 일부 서드파티 키보드
- 예측 변환으로 일부만 친 경우 (たな → 田中): ふりがな가 「たな」로 불완전하면, 사전 후보 중 앞부분이 같은 것(たなか)을 ふりがな 칸 아래에 칩으로 보여 준다
- 따라서 사전은 **삭제하지 않고** ふりがな 칸 밑의 "혹시 이 읽기인가요?" 칩으로만 쓴다. 별도 화면은 없다.

**실기 확인 항목 (D-6주)**: iPhone의 かな 키보드와 ローマ字 키보드, 예측 변환, 성과 이름 한 번에 변환, Gboard·Simeji에서 ふりがな가 제대로 채워지는지 확인한다.

| 성씨+이름 JSON | 7.4MB, **gzip 1.7MB** |

- 한계: **흔한 읽기를 구분하는 순위 정보가 없다** (「田中」는 8개 후보가 동등하게 나옴).

### 7.2 후보 정렬 (점수 합산, 높은 순, 프로토타입 `rank.mjs`)
1. **표기 사전 `ja_reading`**에 있는 읽기 (팀이 확정한 값) → 최상단 (+100)
2. **키보드 입력 힌트**: `compositionupdate` 이벤트로 한자 변환 직전의 히라가나를 잡아, 앞부분이 같은 후보에 가산점 (+10). 예: 「かけ」 타이핑 후 翔 → かける가 1위
3. **흔한 이름 순위표**에 가산점 (직접 정리하는 목록. 흔한 성씨 상위 수백 개 + 흔한 이름)
4. **한자별 정규 읽기 검증 (KANJIDIC2)**: 읽기를 한자 한 글자씩의 훈독·이름용 읽기(nanori)·음독으로 나눠 설명할 수 있는지 계산한다. 연탁(なかじま)과 촉음(はっとり)도 허용한다. 훈독·nanori는 3점, 음독은 2점, 설명 불가는 0점
5. JMnedict 후보 (기본)

**실측 결과 (4번만 적용, 순위표 없이)**
```
田中   → たなか(3) やなか(3) でんちゅう(2) … ぬなか·たなた 등은 0점으로 밀림
佐藤   → さとう(2) さどう(2) … さいう·さいとう는 0점
鈴木 → すずき   高橋 → たかはし   渡辺 → わたなべ   山本 → やまもと   中村 → なかむら   (모두 1위)
服部   → はっとり(3)   佐々木 → ささき   翔 → かける(3) しょう(2)
吉田   → きった(3) よした(3) よしだ(2.75)   ← 순위표로 보정 필요
小林   → おはやし(3) こはやし(3) こばやし(2.75) ← 순위표로 보정 필요
大翔   → ひろと まさと … (요즘 흔한 はると는 한자 읽기로 설명이 안 돼 뒤로 밀림) ← 순위표 필요
```
- 결론: 검증만으로도 **희귀한 읽기는 뒤로 밀린다**. 하지만 그럴듯한 후보 사이의 순서(よしだ > きった, こばやし > おはやし)와 요즘 이름의 특수 읽기(大翔=はると)는 **흔한 이름 순위표가 꼭 필요**하다. 순위표 작업을 일정(D-7주)에 넣었다.
- 현실적으로는 방문자가 일본 키보드로 읽기를 친 뒤 한자로 바꾸기 때문에, 2번(키보드 힌트)이 대부분의 경우 정답을 1위로 올릴 것으로 보인다. 예측 변환을 쓰면 일부만 잡힐 수 있어 실기 확인이 필요하다.
- UI: **상위 3개 + "더 보기" + "직접 입력(히라가나)"**. 0점 후보는 "더 보기"에만 둔다.
- 한자 없이 히라가나나 가타카나로만 쓰면 이 단계 자체가 없다.

### 7.3 데이터 빌드 (빌드 시 1회)
```
JMnedict.xml.gz
  → surname / given·fem·masc 항목만 추출 → 히라가나로 정규화, 중복 제거
  → 순위표 점수 병합
  → dict/full.json.gz        (② ③ 용, 약 1.7MB)
kanjidic2.xml.gz
  → 한자별 음독·훈독·nanori 추출 (13,108자)
  → dict/kanji.json.gz       (약 0.16MB, ①②③ 공통)
  → dict/shard/{첫 글자}.json (① 방문자 웹용, 글자별 수 KB)
```

## 8. 입력 흐름과 QR 데이터

### 8.1 입력 흐름
```
[이름 칸] → [ふりがな 칸 (자동 입력, 비면 사전 후보 칩)] → [호칭 칩] → [결과 확인] → [QR]
  (한글 입력이면 ふりがな 칸은 숨김)        ── 모두 한 화면에서 끝남 ──
```
- 방문자에게는 **이름과 호칭 외에 아무것도 묻지 않는다** (나이대·성별 입력 없음). 호칭은 기본값이 있어 안 눌러도 된다.
- 입력하는 동안 결과를 실시간으로 아래에 보여 준다 (タナカ → 다나카).
- 화면 아래 안내: 「入力した名前は保存されません」 (입력한 이름은 저장되지 않아요)

### 8.2 QR 데이터 형식 (v1)
```
NL1:{"v":1,"dir":"ja2ko","src":["田中"],"read":["たなか"],"out":["다나카"],
     "m":"self","e":0,"id":"k3f9x2","t":1762850000}
```
| 필드 | 설명 |
|---|---|
| `v` | 형식 버전 |
| `dir` | `ko2ja` / `ja2ko` |
| `src` / `read` / `out` | 입력 덩어리 배열 (1개면 성이나 이름만, 2개면 성+이름). 가나 입력과 `ko2ja`에서는 `read` 생략 |
| `h` | 호칭 `san` / `kun` / `chan` / `none` (§6.4) |
| `m` | 입력 모드 `self` / `member` |
| `e` | 사용자가 결과를 수정했으면 1 |
| `id` | 입력 기기에서 만든 짧은 ID. 같은 QR을 다시 스캔하면 감지 |
| `t` | 생성 시각 |

- 약 120바이트 → QR 버전 5~6, 오류 정정 M. 휴대폰 화면에서 쉽게 인식된다.
- QR에는 성별·연령층이 들어가지 않는다. 두 값은 인쇄 기기에서 스태프가 입력한다 (§12).

## 12. 기록과 개인정보

### 12.1 기록 원칙
- 방문자 부담을 없애기 위해 **방문자 대상 통계 수집은 하지 않는다.** 앱이 자동으로 남기는 것은 **인쇄 횟수**뿐이다.
- 기록은 **인쇄 시점에 ③에서만** 1건씩 남긴다 (QR만 만들고 인쇄 안 한 경우는 제외, 재인쇄는 표시만).
- 남기는 항목: 시각, 인쇄 기기, 방향(ko2ja/ja2ko), 재인쇄 여부, 그리고 **스태프가 입력한 성별·연령층(선택)**.
- **이름은 기록하지 않는다.** 성별·연령층도 이름과 연결되지 않아 개인을 알아볼 수 없다.
- 표기 사전에는 성과 이름 조각만 따로 저장하고, 통계 기록과 연결하지 않는다.
- 행사가 끝나면 ③ 기기의 로컬 기록(재인쇄용 이름 포함)을 P5에서 전체 삭제한다.

### 12.2 Supabase 스키마 (도쿄 리전)
```sql
create table print_events (
  client_id   text primary key,          -- 기기에서 만든 ID (중복 업로드 방지)
  printed_at  timestamptz not null,
  device_id   text not null,             -- 인쇄 기기 구분 (main / spare)
  direction   text not null check (direction in ('ko2ja','ja2ko')),
  reprint     boolean not null default false,
  -- 아래 두 값은 스태프가 P2에서 입력 (방문자에게 묻지 않음)
  staff_gender text not null default 'unset'
              check (staff_gender in ('m','f','unset')),
  staff_age    text not null default 'unset'
              check (staff_age in ('child','10s','20s','30s','40s','50s','60p','unset')),
  created_at  timestamptz not null default now()
);

create table spelling_overrides (
  id          uuid primary key default gen_random_uuid(),
  kind        text not null check (kind in ('ja2ko','ko2ja','ja_reading')),
  part        text not null check (part in ('family','given','any')),
  source      text not null,             -- まつもと / 이 / 翔
  value       text not null,             -- 마츠모토 / リ / かける
  device_id   text,
  updated_at  timestamptz not null default now(),
  deleted     boolean not null default false,
  unique (kind, part, source)
);
```
- RLS
  - `print_events`: anon은 **insert만** 가능 (조회 불가)
  - `spelling_overrides`: anon은 select와 upsert 가능 (삭제는 `deleted=true`로 처리)
  - 통계 조회는 Supabase 대시보드나 관리 화면 PIN + 별도 조회 함수(view)로 제한
- 볼 수 있는 것: 일자별·시간대별 인쇄 수, 방향별 비율, (스태프가 입력한 만큼) 성별·연령층 분포
- 스태프가 입력한 성별·연령층은 눈으로 본 추정치다. 정확한 통계가 아니라 대략적인 방문층 파악용이다.

## 15. 위험과 대응

| 위험 | 가능성 | 대응 |
|---|---|---|
| B1이 Bluefy에서 연결 안 됨 | 중 | 서비스 UUID로 찾기 → 전체 장치 표시 → ESC/POS 프린터로 교체 (§3.2) |
| 행사 중 ③의 Bluefy 탭이 닫힘 (오프라인) | 중 | 예비 iPhone 전환 → 핫스폿 → PNG + 공식 앱 (§11) |
| B1 펌웨어 업데이트로 연동이 깨짐 | 낮음~중 | 검증한 뒤 **공식 앱에서 펌웨어 업데이트 금지** |
| 정품 라벨 부족 | 중 | 넉넉히 준비하고 일본 Amazon 등 현지 구매처를 미리 확인 |
| 읽기나 표기가 틀림 | 중 | 표기 사전, 직접 입력, 스태프 수정 → 저장 |
| 외국 이름을 가타카나로 씀 (ウィリアム) | 낮음 | 규칙 변환 결과를 스태프가 고침 (윌리엄) → 표기 사전 저장 |
| 한국어 2글자 입력의 성/이름 구분 불가 (김준) | 낮음 | 한 덩어리로 변환 (キムジュン). 필요하면 띄어쓰기 안내 |
| 표기 사전에 잘못된 값이 공유됨 | 낮음 | 관리 화면에서 삭제, 최근 수정 목록 확인 |
| 인쇄 iPhone 배터리 | 중 | 보조배터리, 자동 잠금 끄기, 2대 운영 |
| 문구 일본어가 어색함 | 중 | 원어민 감수 후 확정 |

## 16. 결정 현황

| # | 항목 | 상태 |
|---|---|---|
| 1 | 「つ」 표기 | ✅ 기본 `auto`(어두 츠 / 어중 쓰) + 표기 사전으로 이름마다 덮어쓰기 |
| 2 | 라벨 문구 | ⏳ §9.2 후보에서 선택, 원어민 감수 |
| 3 | 라벨 수량 | ✅ 프린터 2대, 라벨은 넉넉히 (정확한 롤 수는 롤당 매수를 확인한 뒤) |
| 4 | 통계 | ✅ 방문자 대상 통계 없음. 앱은 인쇄 횟수만, 성별·연령층은 스태프가 선택 입력 |
| 4-1 | 이름 입력 | ✅ "불리고 싶은 이름" 한 칸, 가타카나 포함 모든 글자 허용, 방향 자동 판별 |
| 5 | 입력 기기 | ✅ 팀원 개인 폰 (Safari 홈 화면 웹앱, 오프라인 가능) |
| 6 | 개발자 계정 | ✅ 사용 안 함 → Bluefy 경로 |
| 7 | 관리 화면 PIN과 접근 범위 | ⏳ 누가 표기 사전을 고칠 수 있게 할지 |
| 8 | 인쇄 담당 iPhone 2대 | ⏳ 누구 폰으로 할지 (Bluefy 설치 필요) |
| 9 | 라벨 호칭 | ✅ 방문자가 さん / くん / ちゃん / 名前だけ 중 선택 (기본 さん), 라벨은 상 / 군 / 짱 / 이름만 (§6.4) |
